## Source and route review notes

- Reconciliation read returns the Run/employee version, request span, gateway call ID, checkpoints (redacted to metadata), grant limits/expiry, lease, usage status, dispatch guard, evidence events, and prior decisions. Cost remains `unknown`.
- Classification distinguishes a completed call, confirmed pre-HTTP failures, a queued cancellation with no call span, and unresolved states. It does not fabricate an outcome from the Owner’s unresolved note.
- The only action currently exposed is `record_unresolved_keep_guard`; there is no force-unlock or automatic redispatch action. Writes use the Owner write dependency, which enforces session/CSRF/Origin, and are scoped to the authenticated company/environment.
- Late-usage implementation only accepts adapter-sourced gateway-final usage with a matching gateway call ID, writes a correction row/event, and leaves a fenced execution outcome unchanged (`service.py`, `record_usage_correction` / `finish`). The focused probe also verified the correction is surfaced by the reconciliation read model without altering the original call/run outcome.
- The three skipped cases and the deprecation warning are reported separately; they do not mask a failed test.
